做个人站这件事，方案多到容易卡在选型上。云主机加博客程序是一套，Serverless 加数据库是一套，还有各种托管平台的一键模板。我最后选了最笨的一种：构建成纯静态文件，扔到 nginx 后面。

## 三个理由

**第一，它不会坏。**

动态站挂着的东西太多：运行时、数据库连接、反向代理配置、定时任务。任何一层出问题，页面就是白的。静态站只有一种失败模式——nginx 挂了。而 nginx 挂这件事，通常是整台机器都没了。

**第二，它快得不需要优化。**

没有数据库查询，没有模板渲染，没有首字节等待。请求进来，nginx 直接从磁盘读文件返回。我第一次部署完盯着 `curl` 的耗时看了半天，因为它太快了，快到我以为是缓存。

**第三，它能活很久。**

十年后回头看，一套 Node 20 加某个 ORM 加某个博客框架的组合，多半已经跑不起来了。而一堆 `.html` 文件，只要还有浏览器，就还能打开。

## 代价是什么

纯静态不是没有成本，成本在**写之前**。

写文章要有构建流程。想加个评论，得接第三方。想按阅读量排序，做不到——没有后端就没有统计。想在站内搜索，得在构建时把索引切好、塞进静态文件。这些都不是不能做，但每一样都要提前想清楚。

我选的解法是这样：

- **文章**用 markdown 写，构建时转成 HTML。
- **搜索**用 Pagefind，构建完成后扫一遍产物，切出索引文件，浏览器里加载 WASM 跑检索。零后端。
- **评论**先不做。真需要了再接一个第三方服务，前端留好位置就行。
- **访问统计**先不做。我个人不想为了看个数字，往页面上塞一段别人的脚本。

## 一个具体的取舍

我一开始想用 React 写，毕竟熟。后来算了一下：这个站上真正需要交互的，只有搜索框和几个工具页。为了这些挂一个 React 运行时，等于让每个读文章的人下载几十 KB 用不上的代码。

换成 Astro 之后，默认输出零 JS。只有工具页那些 `<script>` 会被打包进去，而且只在那几个页面加载。首页和文章页是纯粹的 HTML 加一点 CSS。

这个差别在网速好的时候看不出来，在手机上用流量看的时候能感觉出来。

## 关于国内访问

这一点值得单独说，因为它改变了我几个默认选择。

不能引 Google Fonts——会卡住。不能引国外 CDN 上的任何东西——同样会卡住，而且卡住的时候页面会白屏等超时。所以我做了三件事：

1. 字体只用系统字体栈，不下载任何字体文件。
2. 所有 CSS 和 JS 都在构建时打进产物，不外链。
3. 图片如果有，放本地。

结果是整个站没有任何跨域请求。打开就是打开，不用等谁。

## 最后

如果你也在犹豫要不要给个人站上后端，我的建议是先别上。等你真的遇到了静态解决不了的问题，再上。多数人的博客，一辈子都不会遇到那个问题。
